# True or Not 기획서

기준일: 2026-10-03. DB 호스팅 결정 추가: 2026-10-04. 역할: 제품 목적·범위·확정 정책. 구현 사실은 [아키텍처](아키텍처.md), 미결정 정책과 작업 상태는 [작업현황](작업현황.md)을 따른다. 기존 v4의 제품 내용을 통합한 현행 기획서다.

## 제품 목적

True or Not은 기사·댓글·온라인 주장에 의문을 가진 사용자가 개별 주장과 근거를 추적·비교하는 생활형 검증 도구다. 입력에서 확인할 주장을 추출하고 실제 자료의 인용·수치·날짜·비교 조건을 연결해 확인된 내용과 불확실한 내용을 함께 보여준다.

온라인 텍스트에는 사실·의견·예측·과장·오래된 정보가 섞여 있다. 같은 발표를 재인용한 여러 기사나 기간·지역이 다른 통계가 독립적인 확인 또는 직접적인 반박으로 오해될 수 있다. 사용자가 결론의 한계와 연결된 원문을 이해하는 것이 목표다.

## 대상과 활용 상황

| 상황 | 확인할 내용 | 제공할 정보 |
|---|---|---|
| 생활 물가 기사 | 어떤 상품이 언제 얼마나 올랐는가 | 기간·대상·단위가 맞는 근거 |
| 정책 관련 댓글 | 확정 정책인가, 검토안인가 | 발표·시행 시점과 정책 상태 |
| 문화 행사 정보 | 올해 일정인가, 과거 기사인가 | 행사 연도·지역·공식 공지 |
| 과장된 문장 | 사실 부분과 해석은 무엇인가 | 사실 요소와 의견, 빠진 맥락 |

## 제공하는 흐름

1. 텍스트·링크와 확인 요청을 입력한다. 외부 서비스로 전송하기 전에 명시적 전송 동의를 확인한다. 이미지 경로도 구현되어 있으나 공식 제공 범위는 D4에서 결정한다.
2. 내용 요약 요청은 검증과 구분해 요약을 제공한다. 짧은 대화는 의도 분류를 거쳐 검증 또는 답변으로 분기한다.
3. 최대 3개 주장을 자동으로 추출·검증한다. 검증 전 후보 선택 단계는 현재 없다.
4. 결과에서 주장별 판정·인용·출처·조건·경고와 AI 개요를 읽고 원문을 확인한다.
5. 취소·재요청과 JSON 내보내기를 제공한다. 데모는 합성 예시로 명시한다.

2026-10-05 최초 외부 전송 동의(T11)를 구현·검증하였다. 첫 외부 호출 전에 안내 후 ‘동의하고 시작’을 선택하며, 같은 사이트·브라우저의 다음 질문과 새로고침에서는 동의를 유지한다. 거절·닫기는 외부 호출 없이 입력을 보존한다. 동의 철회·사이트 데이터 삭제·안내 버전 변경 시 다시 확인하며 대화 저장 선택과 구분한다. 공개 배포와 법적 검토 완료를 뜻하지 않는다.

대화 저장 체크박스는 사이드바가 아닌 최초 동의 창의 선택 항목으로 제공한다. 이후에는 웹 하단 ‘대화 저장 설정’에서 변경하며 상세 안내는 하단 개인정보 처리방침에서 확인한다. 확정 버튼을 누를 때만 적용하고 거절·취소·닫기는 기존 설정을 유지한다. 처음에는 꺼짐이며 확정한 선택은 같은 사이트·브라우저에서 새로고침 후에도 유지한다. localStorage에는 별도 안내 버전만 기록하고 대화 본문·소유권 쿠키는 넣지 않는다. 저장 해제·사이트 데이터 삭제·안내 버전 변경 시 꺼지고 다른 탭의 해제도 반영한다. 저장소 차단은 현재 화면에만 적용된다고 안내한다. 대화 소유권은 별개인 유효한 익명 쿠키로 확인한다.

## 제품 원칙

2026-10-05 모델 추가: Auto는 설정된 모델 중 DeepSeek V4.1 Flash MAX → GPT-6 Luna MAX/Fast → Gemini 3.8 Flash HIGH → Gemini 3.7 Flash HIGH 순서로 시도한다. 기존 모델을 제거하지 않는다. DeepSeek는 Experiential 게이트웨이를 사용하고 구조화 JSON을 기존 서버 검증으로 확인한다. 기존 검색 도구는 유지하며 전송 대상 추가에 따라 외부 전송 안내를 v2로 갱신한다. 별도 대화 저장 선택·쿠키 소유권은 변경하지 않는다. 실연결의 확인 범위는 [QA 기록](qa/실행기록/2026-10-05-DeepSeek.md)을 따른다.

- 검색 결과 부재를 거짓의 증거로 사용하지 않는다. 직접 근거가 부족하면 결론을 유보한다.
- 실제 수집 원문과 대조한 인용을 근거로 제공한다. AI 설명·검색 요약을 원문 인용으로 표시하지 않는다.
- 기간·지역·단위·대상·모집단이 다른 자료는 먼저 비교 조건을 확인한다.
- 출처 수와 독립적인 근거 수를 구분한다. 공식 출처나 금융 매체라는 이유만으로 확인 판정·가산점을 주지 않는다.
- 사실·의견·예측을 구분한다. 미래 결과를 현재 확정하거나 의견을 거짓으로 판정하지 않는다.
- 입력·수집 문서의 지시문은 비신뢰 데이터로 취급한다. 접근 차단·로그인·유료벽을 우회하지 않는다.
- 검증 시각·범위·한계와 데모 여부를 표시한다. 측정하지 않은 서비스 정확도 수치를 홍보하지 않는다.
- 처리 생략·처리 실패와 근거 부족의 의미를 구분한다. 현재 개요 상태 표시의 불일치는 T14에서 관리한다.

## 판정의 의미

| 판정 | 의미 |
|---|---|
| 대체로 확인됨 | 핵심 사실·조건과 직접 관련된 근거가 일치 |

### JEV 유형 분류·동의·공통 호출 한도

| 요구사항 | 적용 정책·완료 기준 |
|---|---|
| JEV 유형 분류 | 메인 검증의 JEV 옵션과 빠른 경로 모두 추출·유형 분류를 적용합니다. 입력 전체를 사실 주장 1개로 고정하지 않으며 사실·의견·예측·불명확한 주장을 구분합니다. 혼합 입력은 사실 요소만 검증하고 의견·예측을 현재 확정된 사실로 점수 판정하지 않습니다. 분류 불가 시 판단을 유보하고 판정 엔진·실제 모델·전환 여부를 표시합니다. |
| 최초 전송 동의 | intent·검증·JEV·요약의 첫 외부 호출 전에 대상·목적·수신 서비스를 안내하고 ‘동의하고 시작’ 선택을 받습니다. 같은 사이트·브라우저에서 안내 버전만 localStorage에 저장해 다음 질문과 새로고침 후에도 유지합니다. 동의 철회·사이트 데이터 삭제·안내 범위 변경 시 재확인하며 저장 차단 환경에서는 현재 화면에서만 유지합니다. 서버는 누락·false·문자열·숫자·null 동의를 외부 호출 전에 거부합니다. 재탐색은 같은 유효 범위 안에서 실행하며 대화 보관 동의를 자동 활성화하지 않습니다. |
| 공통 호출 한도 | 메인·보조 API에 공통 접근·동시 실행·사용자별 횟수·비용 정책을 적용합니다. 모델 폴백과 내부 재탐색의 추가 사용량도 같은 예산에 포함하며 경로 변경 시 초기화하지 않습니다. 여러 인스턴스에서도 한도 우회를 막고 초과 요청을 외부 호출 전에 차단합니다. 수치·집계 기간·공통 제한 구현 방식은 D11에서 결정합니다. |

공유 시크릿은 프록시와 백엔드 간 보호 수단이며 이용자 인증·대화 소유권 검사·호출 한도를 대신하지 않습니다. 최초 동의 유지·철회·재확인 방식은 D12에서 확정·구현하였습니다. `consent=true`는 요청의 동의 확인 값이며 로그인이나 위조 요청 방지 인증이 아닙니다. 수신국·제공자의 처리/보관 조건·운영자 정보와 법적 요건 검토는 공개 준비(T26)에 남습니다.

### 근거 부족·생성 생략·생성 실패 구분

주장 판정과 AI 개요 생성 상태를 별도로 관리합니다. 백엔드 계약·프론트 검증·화면·대화 저장에 같은 의미를 적용하며 기술 장애를 사실 판정의 근거로 사용하지 않습니다.

| 상태 | 의미·안내 |
|---|---|
| 근거 부족 | 검증은 수행했으나 직접 근거를 확보하지 못했거나 비교 조건이 부족합니다. 사실·거짓을 단정하지 않고 확인 범위와 부족한 조건을 설명합니다. 적절한 판단 유보는 정상 결과로 취급할 수 있습니다. |
| 생성 생략 | 개요 생성 조건이나 대상이 없어 생성 호출을 의도적으로 하지 않았습니다. 생략 이유를 표시하고 호출하지 않은 모델이나 생성 완료된 개요가 있는 것처럼 표시하지 않습니다. |
| 생성 실패 | 생성은 시도했으나 공급자 오류·시간 초과·응답 형식 또는 인용 검증 오류로 유효한 개요를 만들지 못했습니다. 처리 실패와 재시도 가능 여부를 안내합니다. 이미 유효하게 검증된 주장·근거는 보존하고 생성 실패를 근거 부족으로 바꾸지 않습니다. |

유효한 개요가 생성된 경우에는 생성 완료로 표시합니다. 근거 부족은 주장 판정, 생략·실패·완료는 생성 상태이므로 함께 나타날 수 있습니다. 필드명·기존 계약 이행 방식은 T14에서 구현하며 저장한 대화에도 동일하게 적용합니다.

### PostgreSQL 기반 대화 저장·불러오기

#### DB 호스팅·연결

- 2026-10-04 사용자 결정으로 대화 저장 DB는 관리형 **Render PostgreSQL**을 사용합니다. 프론트엔드는 FastAPI를 통해서만 대화를 저장·조회하며 DB에 직접 접속하지 않습니다.
- Render 백엔드와 DB는 같은 워크스페이스·리전에 배치하고 내부 연결 주소를 백엔드 전용 `DATABASE_URL`로 관리합니다. 로컬 개발 등 외부 접속은 TLS와 허용 IP 제한을 적용합니다. 실제 접속 정보는 문서·저장소·프론트엔드·로그에 기록하지 않습니다.
- DB 선택 확정과 리소스 생성·테이블·API 구현·실환경 검증은 구분합니다. 현재 Free·Singapore DB 생성·로컬 연결·DB 제한 시간은 D13, 익명 소유권·별도 저장 동의·사용자 삭제는 D17에서 확정·구현 완료했습니다. 지속 운영 비용·만료 대응·보관 기간·자동 삭제·백업만 미결정으로 관리하며 공개 배포·원격 검증은 별도입니다. 유료 생성·전환은 별도 승인 없이 실행하지 않습니다.

#### 목적과 최소 범위

- 저장에 동의한 대화의 사용자 메시지와 화면에 제공한 assistant 답변을 PostgreSQL에 저장합니다. 새로고침·백엔드 재시작·재배포 후에도 같은 소유자가 대화 목록과 메시지를 불러와 이어갈 수 있어야 합니다.

### 공개·시연의 통과 조건

- 공개·시연 대상 경로의 P0 문제는 수정·검증하거나 해당 경로를 비활성화하고 대상에서 명시적으로 제외합니다. 유형 미분류·동의 누락·한도 우회·타인 대화 접근을 화면 경고만 붙여 허용하지 않습니다.
- 동의가 없거나 유효한 공통 한도를 초과한 요청은 외부 호출 0회를 확인합니다. 대화 저장 경로는 보관 동의와 서버 소유권 검사·삭제 시험을 추가로 통과해야 합니다.
- 코드 구현, 모의 어댑터 시험, 실제 공급자 호출, 원격 배포·화면 검증의 완료를 각각 기록합니다. 실제 공급자 1회 성공이나 과거 테스트 통과 수만으로 전체 기능을 합격 처리하지 않습니다.
- 공개·시연에 포함할 입력·모델·경로를 먼저 고정하고 해당 범위의 모의 회귀, 실제 공급자 요청, 제공 환경의 요청·응답·화면 확인을 통과해야 합니다. 로컬 시연 성공을 Render 공개 성공으로 대신하지 않으며 미검증 경로는 비활성화합니다. 동의 거부·한도 초과·권한 오류 등의 차단·장애 조건은 모의 시험으로 확인할 수 있으나 실제 공급자 정상 동작의 증거와 구분합니다.
- 각 합격 기록에는 코드 리비전·미커밋 여부·모델/설정·사례·실행 시점·원본 증거를 연결합니다. 미실행·미확인 및 미결정 통과 기준은 Pass로 표시하지 않습니다.
- 운영·개인정보·동의 안내와 문서 공유 권한을 실제 제공 범위에 맞춥니다. 내부 전용 문서의 공개 열람·편집 권한은 별도로 확인하며 문서의 내부 전용 표기만으로 접근 통제가 된 것으로 판단하지 않습니다.

### 성능·비용·정확도 표현 기준

- 원문 문자열 일치·참조 무결성 검사와 사실성·맥락·출처 독립성 평가를 구분합니다. 검사 조건이나 제한된 사례의 통과를 서비스 정확도 또는 모든 결과의 정합성 100% 보장으로 표현하지 않습니다.
- 요청당 LLM 4회·출력 28,000토큰 같은 합계는 특정 경로의 설정값일 뿐 서비스 전체의 실측 비용이나 최대 사용량이 아닙니다. 검색 API/모델 웹검색, intent, 주장 수, 폴백, 재탐색, 실제 추론·토큰 사용량에 따라 달라지므로 실행 조건과 함께 기록합니다.
- 비용은 기준일과 공급자의 공식 요율을 명시하고 입력·출력·별도 청구되는 추론 사용량, 검색/API 호출, 처리 등급, DB·배포 비용을 구분합니다. 중복 집계하지 않으며 추정치와 실제 청구·관측값을 분리합니다. 근거 없는 약 2배 요금이나 요율이 빠진 토큰 합계만으로 운영 비용을 확정하지 않습니다.
- 응답 속도는 전체 요청·재탐색·DB 처리 시간을 함께 측정합니다. 설정한 시간 상한을 평균 응답 속도나 완료 보장으로 설명하지 않으며 DB 저장을 위해 추가 LLM 요약 호출을 넣지 않습니다.
- 공통 호출 비용 한도는 D11, 지속 운영의 DB 비용·무료 만료 대응은 D13, 사례·허용 추가 지연·합격 기준은 D14에서 확정합니다. 이미 적용한 무료 DB 구성·접속 보호·DB 제한 시간과 미결정 운영 정책을 구분하며 이번 문서 정리로 유료 서비스 생성, 실제 API 시험 또는 배포를 실행하지 않습니다.

## 화면과 안내

한국어 다크 화면에서 입력·원문·주장·근거를 연결하고 모바일에서도 선택을 유지한다. 원문 강조와 주장 선택, 인라인 출처, 날짜·비교 조건·접근 상태를 읽기 쉽게 표시한다. 키보드·포커스·reduced-motion과 가로 넘침은 QA 기준으로 확인한다.

소개 문구: “그 주장, 근거까지 보이나요? True or Not은 주장과 출처를 연결해 확인된 내용과 불확실한 내용을 함께 비교하는 검증 도구입니다.”

데모 안내: “데모 모드입니다. 표시된 주장·출처·결과는 화면 흐름을 설명하기 위한 예시이며 실제 검증 결과가 아닙니다.”

결과 안내: “이 결과는 표시된 검증 시각에 접근한 자료를 기준으로 작성되었습니다. 검색 범위와 자료 접근에 한계가 있으며, 새로운 자료에 따라 달라질 수 있습니다. 중요한 판단 전에는 연결된 원문을 직접 확인해 주세요.”

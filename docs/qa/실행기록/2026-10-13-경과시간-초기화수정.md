# 2026-10-13 [bsj] 검증 경과 시간 초기화 수정

## 확인한 원인

사용자께서 ‘가져온 원문 · 33초’ 아래에 ‘검증 완료 · 0초 경과’가 표시되는 문제를 제보하셨습니다. 최신 `main`을 가져온 `feat/frontend`의 `d5d95cc`를 기준으로 확인했습니다.

`ProgressReply`의 타이머는 `statusStage` 변경마다 현재 시각을 새로운 시작 시각으로 지정하고 표시 값을 0으로 만들었습니다. 결과 수신 때 `statusElapsedSeconds`에 전체 시간을 저장했지만 화면은 이 값을 사용하지 않았습니다. 따라서 검색·읽기·판정 단계가 바뀔 때 초기화되고 마지막 정리 단계가 짧으면 완료 시간이 0초로 남았습니다.

## 변경

- 진행 메시지에 요청 시작 시각과 현재 누적 시간을 함께 보관합니다.
- 타이머는 같은 요청의 시작 시각을 사용하며 단계 변경에 영향을 받지 않습니다.
- 상단에 ‘총 N초 경과’를 표시하고 완료·오류·취소 시 저장된 종료 시간을 유지합니다.
- 시간 계산은 기존 대시보드 파일 안에서 진행 표시와 취소 처리에 함께 사용합니다.
- 이전 실행 기록의 검색·원문 읽기 개선과 달리 이번 변경 범위는 경과 시간 표시입니다.

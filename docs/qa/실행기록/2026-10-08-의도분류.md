# 의도 분류·일반 질문 처리 검증 (2026-10-08)

## 요약

일반 질문·접근 문제·이미지 설명을 자동 검증하지 않도록 요청 의도를 먼저 분류합니다. 분류 실패는 검증으로 넘기지 않습니다. 기존 `feat/agent`에서 진행하였으며 실제 공급자 정확도·응답 시간 개선을 완료로 표시하지 않습니다.

## 변경 범위

- LLM 출력: `verify`·`reply`·`clarify`, `current`·`previous`, 링크 본문 읽기 필요 여부. 명시적 모델 단독 사용과 Auto 공급자 순서를 유지합니다.
- 맥락: 이전 답변·주장·출처 접근 상태·경고, 확인 대기 원문 최대 12,000자·기존 검증 범위·링크·이미지.
- 분류 프록시: 입력 읽기 중 3 MB 상한, 동의·취소 검사, 응답 계약 검사. 의도 대기 제한은 45초입니다.
- UI: 모든 자료의 의도 판단, 대기 자료 교체·보존, 분류·요약 중 중단, 취소 요청 격리, 0개 주장 결과의 로딩 종료 및 다른 원문 결과로 교체.
- `ㅎㅇ`·`개새야`는 모델 분류 실패 시에도 인사·안내로 답변합니다. 실질적인 검증 문장이 포함되면 검증을 추측하지 않습니다.

## 브라우저·실행 서버

- 외부 모델·실제 DB를 호출하지 않는 `backend/tests/browser/intent_fixture.py`를 8017에서, 해당 서버를 사용하는 Next production을 3017에서 실행했습니다. 자동 테스트와 이 합성 UI 검증은 실모델 품질 평가와 구분합니다.
- 일반 접근 문의·링크 접근 문의는 검증·요약 호출 없이 답변했습니다. 링크 내용 설명만 요약 호출 1회를 사용했습니다.
- 최종 회귀에서 intent 9회·검증 4회를 관찰했습니다. 4건은 명시적 현재 검증, 확인 질문 후 자료 B 검증, 합성 실패 검증, `요약해줘` 본문+별도 사실 검증 요청입니다. 마지막 일반 질문에서 검증 호출은 늘지 않았습니다.
- 확인 질문 후 제출된 자료 B와 `가격 주장만 / 검증해줘`를 확인했습니다. 이전 자료 A 대신 B가 대시보드에 표시되고, 주장 0개 결과도 입력 대기로 종료했습니다. 분류 중 취소 뒤 다음 실패의 오류·재입력을 확인했습니다.
- 실행 중인 8010 OpenAPI는 이전 `IntentRequest(text,consent,context,modelPreference)`·이전 context 3필드였으며 자동 reload가 꺼져 있었습니다. 새 프론트의 추가 필드를 받을 수 없어 반복 실패 안내가 발생했습니다. 같은 포트에서 백엔드를 재시작한 뒤 `focus,image,linkUrl`과 새 맥락·12,000자 상한을 확인했습니다. 기존 3000 프론트는 유지했습니다.
- [합성 검증 화면](2026-10-08-의도분류.png)을 저장했습니다. 임시 3017·8017 서버와 검증 탭은 종료하며 사용자 3000·8010 서버는 유지합니다.

## 미검증·제한

- 실제 외부 모델 호출은 자동 승인 검토가 첨부 이미지·맥락의 특정 외부 목적지 전송 승인이 없다는 이유로 거절하여 실행하지 않았습니다. 실제 의도 분류 정확도·지연·비용은 미측정입니다.
- Chrome 확장에 로컬 파일 접근 권한이 없어 이미지 업로드 UI는 완료하지 못했습니다. 이미지 요청 계약·1회 vision 호출·후속 이미지 보존은 모의 HTTP 및 프론트 테스트로 검증했습니다.
- 공개 배포·실제 DB 통합·공통 비용 한도 및 JEV 자체 유형 분류는 이번 완료 범위가 아닙니다.

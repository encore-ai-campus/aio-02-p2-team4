# 검증 진행 시간 표시 수정

기준일: 2026-10-13. 기존 `feat/agent`에 최신 main `a89395a`를 보존하여 반영했습니다.

## 원인과 변경

- 오른쪽 시간은 `statusStage`마다 초기화됐으며, 로더는 별도로 마운트된 시점부터 계산했습니다. 출처 원문 옆 시간은 전체 요청 시작 이후의 누적 완료 시점이었습니다.
- 전체 요청 시작 시각·최근 이벤트 시간·종료 시간을 사용합니다. 로더와 오른쪽 표시에 동일한 경과 값을 전달하고 완료·오류·중단 뒤에는 고정합니다. 완료 시점은 `요청 후 N초에 완료`로 표시합니다.
- 타이머 계산은 0.1초 정밀도를 유지하며 기존 1초 화면 갱신 주기를 유지합니다. 검증 결과·LLM 호출·백엔드·CSS는 변경하지 않습니다.

## 검증

- 환경 파일 없는 임시 복사본의 FE 3017·모의 백엔드 8017로 재현했습니다. 수정 전 22초 시험 스트림의 완료 표시가 `9초 경과`, 원문 완료 시점이 `12초`로 역전됐습니다. 모의 스트림에는 추출·검색·읽기·검증·재탐색이 포함됩니다.
- 수정 후 진행 중 로더 `18.3s`와 오른쪽 `총 18.3초 경과`가 일치했습니다. 의도 분류·전송을 포함한 완료 시간 `23.1초`를 고정하고 원문을 `요청 후 13.2초에 완료`로 표시했습니다. 오류 종료 시간 `22.3초`도 이후 조회에서 유지되며 로더가 종료됐습니다.
- 중단용 모의 스트림에서 로더·오른쪽 `33.4초` 일치와 원문 완료 시점 `12.2초`를 확인했습니다. 사용자가 누르는 중단 버튼으로 종료하여 `35.5초`를 고정하고 로더를 제거했습니다.
- `node --experimental-strip-types --test app/lib/progress-timing.test.mjs`: 회귀 5개 통과. 단계 전환·완료·오류/중단·시계 표본 역전·기존 기록을 검증했습니다. 새 모듈 생성 전 import 실패는 기존 동작을 재현한 행동 회귀로 집계하지 않았습니다.
- `npm test`: 전체 FE 149개 통과, 실패 0개. `npm run typecheck` 및 별도 복사본의 `npm run build -- --webpack`: 통과했습니다.
- 시험 탭과 FE·모의 백엔드 프로세스를 종료했습니다. 3017·8017 리스너가 없고 기존 사용자 3000(PID 9612)이 유지됨을 확인했습니다. 확장이 주입한 HTML 속성의 개발 모드 hydration 경고는 시간 표시 수정 범위에 포함하지 않았습니다.

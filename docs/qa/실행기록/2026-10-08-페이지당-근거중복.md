# 2026-10-08 [bsj] 페이지당 근거 표시 및 1차 요약 지연 분석

## 변경 내용

- 검증 요청에서 한 주장에 대해 같은 출처 페이지가 여러 인용문으로 반복되면 최종 근거 카드에는 첫 번째 검증 인용 하나만 남깁니다.
- 판정은 표시 제한 전의 모든 원문 확인 인용을 사용합니다. 같은 출처에서 지지·반박이 함께 나오면 기존처럼 `insufficient_evidence`로 유보하는 동작을 유지합니다.
- 검증 모델 지침에도 한 페이지에서 가장 강한 인용 하나만 선택하도록 추가했습니다.
- 진행 미리보기는 이미 출처당 인용 하나로 제한되어 있었습니다. 이번 변경으로 최종 결과도 동일한 기준을 따릅니다.

## `1차 요약 · 111초` 분석

- 프런트엔드 타이머는 검증 요청을 제출할 때 시작하며, 짧은 문장에서는 intent 분류 호출도 그 시간에 포함됩니다.
- 서버는 `verifying` 단계가 끝난 뒤 1차 미리보기를 내보내고, 그 다음에 `synthesizing` 최종 답변을 시작합니다. 따라서 이 숫자는 요약 생성 시간이나 최종 답변 대기 시간이 아니라 **요청 제출부터 검증 미리보기까지의 전체 시간**입니다.
- 미리보기 생성은 검증 결과를 계약 형식으로 정리하는 서버 처리이며 별도 LLM 호출이 아닙니다. 화면에 같은 페이지의 카드가 여러 개 보였다고 해서 페이지 검증을 카드 수만큼 다시 호출한 것은 아닙니다.
- 사용자가 제공한 2026-10-08 속도 분석 자료에서는 `verifying` 평균 약 31초, 일부 101~146초, 최대 229초 timeout 사례가 보고되었습니다. 코드에서 공급자 호출은 순차 폴백이며 모델별 요청 제한시간은 90초입니다. 그래서 111초 사례는 검증 모델 응답 지연 또는 폴백이 주된 원인일 가능성이 높습니다.
- 저장소에서 해당 화면과 일치하는 캡처 JSON은 찾지 못했습니다. 이미지의 111초를 추출·검색·읽기·검증 각각으로 나눈 정확한 시간은 확인할 수 없습니다. 페이지당 카드 제한만으로 111초가 줄어드는지도 실측 전에는 단정하지 않습니다.

# True or Not QA 검증기준

기준일: 2026-10-03. 역할: 사례·통과 기준·평가 방법. 이 표는 통과 결과 목록이 아니다. 실제 결과는 [실행기록](실행기록/)에 날짜별로 남기고, 미완료 작업은 [작업현황](../작업현황.md)을 따른다.

## 입력과 실행기

- 실행 입력·focus·예상값의 기준은 [qa_cases.json](../../scripts/qa_cases.json)의 E01~E20이다. 입력을 문서에 중복 복사해 따로 수정하지 않는다.
- 자동 실행기는 [qa_baseline.py](../../scripts/qa_baseline.py)다. 현재 로컬 백엔드 고정, 공유 시크릿 헤더 미지원, HTTP 오류 시 총 최대 4회 요청, 기존 결과 파일이 있으면 건너뛰는 동작이 있다. T19에서 원격·재요청·코드 기준 기록을 보완한다.
- 예전 10선의 예상값과 수동 결과는 [보존본](../archive/2026-10-03/QA-예문-10선.md)에 남긴다. 예상은 검토할 초안이며 결과에 맞춰 사후 변경하지 않는다. 변경 필요 시 근거·날짜와 함께 별도 수정한다.
- 유료 API 실행 사례·반복 수·예산·담당은 D14에서 정한다. 오프라인 테스트와 실제 공급자 요청을 구분한다.

## 오프라인 회귀 명령

저장소 루트 기준이다. 첫 명령은 실제 키가 테스트 fixture를 덮지 않도록 해당 프로세스에서만 제외하고 실제 DB 연결을 비활성화한다. 개인 설정 파일은 바꾸지 않는다. 다른 플랫폼의 실행 방법은 [백엔드 안내](../../backend/README.md)를 따른다.

```bash
cd backend
env -u OPENAI_API_KEY -u GEMINI_API_KEY -u GOOGLE_API_KEY -u YOUTUBE_API_KEY -u TAVILY_API_KEY -u SERPAPI_API_KEY -u TYPESAFE_API_KEY -u FINNHUB_API_KEY DATABASE_URL= .venv/bin/python -m pytest -q
cd ..
npm test
npm run typecheck
npm run build
```

`npm test`는 Node의 기본 테스트 발견으로 요약·JEV route를 포함한 테스트를 실행한다. 새 API 경계 테스트도 기본 발견 규칙에 맞는 이름으로 작성한다. 위 명령의 기재는 실행 완료를 뜻하지 않는다. 변경 후 필요한 회귀를 수행하고 실행한 명령·결과를 기록한다.

### GitHub Actions CI

[CI workflow](../../.github/workflows/ci.yml)는 main 푸시·PR·수동 실행에서 다음 두 작업을 병렬 실행한다. 액션은 커밋 SHA로 고정하고 저장소 권한은 읽기로 제한한다. 실제 공급자 키·DB URL과 운영용 환경 파일은 사용하지 않는다.

| 작업 | 환경·검증 |
|---|---|
| 프론트엔드 | Node.js 24, `npm ci` → `npm test` → `npm run typecheck` → `npm run build` |
| 백엔드 | Python 3.12·uv 0.12.23, `uv lock --check` → `uv sync --frozen` → `uv run --no-sync pytest -q` |

오프라인 CI 결과를 실제 공급자·공개 배포·DB 통합 시험의 성공으로 해석하지 않는다. 실행 결과는 날짜별 실행기록에 남긴다.

## 전후 평가

| 지표 | 정의·주의점 |
|---|---|
| 태스크 완료율 | 사전 기대 행동·결과를 충족한 사례 / 전체 사례. 정당한 의견 제외·판단 유보는 성공 가능, 처리 실패는 별도 |
| 도구·복구 행동 선택 정확도 | 사전 허용 행동과 일치한 선택 / 평가 가능한 선택. 고정 도구 순서를 자율 선택 정확도로 보고하지 않음 |
| 응답 일관성 | 동일 입력·조건의 반복 묶음에서 판정·처리 상태가 일치한 비율. 문구 일치가 기준은 아님 |
| 평균 내부 복구 횟수 | 요청 내부 복구 횟수 합 / 전체 요청. 공급자 폴백·사용자·HTTP 재요청과 분리 |
| 인용·비교 정합성 | 원문 일치·참조·비교 조건·탈락 이유를 사례별 기록. 정합성이 전체 사실 정확도와 같지는 않음 |
| 시간·비용 | 요청 전체와 내부 재탐색의 시간·호출 수·토큰/검색 사용량. 실제 측정값만 표시 |

현재 공개 결과에는 전체 `recoveryTrace`가 없다. T19에서 평가용으로 원인·횟수·시간을 관측하는 방법을 정하되 원문 전체·키·원시 사고 과정을 로그에 남기지 않는다. 코드·모델·추론·설정·사례·예상값을 고정하고 신규 복구와 기존 실행을 비교한다. 기존 mini 1회 관측을 서비스 정확도나 반복 일관성으로 해석하지 않는다.

## 실행기록 형식

새 결과는 `실행기록/YYYY-MM-DD-주제.md`에 작성한다. 같은 날짜의 서로 다른 실행은 이름을 구분하고 기존 결과를 덮지 않는다.

| 필드 | 기록할 내용 |
|---|---|
| 기준 | 실행 일시, 커밋과 미커밋 여부, 모델·추론·환경 |
| 조건 | 모의/실제 공급자, 입력 ID·예상값·반복 수·예산 |
| 실행 | 정확한 명령, 실행한 사례 수, 통과·실패·미실행·미확인 |
| 관측 | 실제 판정·인용·처리 상태, 내부 복구·외부 재요청·폴백, 시간·비용 |
| 증거 | 원본 결과 경로·코드 기준. 없는 파일·미집계 지표를 증거로 표시하지 않음 |
| 정리 | 임시 서버·브라우저 종료, 미해결 문제와 연결된 T 번호 |

부트캠프 산출물은 현재 그래프·타입 상태·분기·도구 호출을 설계서로, 복구 성공·소진·취소와 전후 지표를 시험 보고서로 구분한다. 단기 컨텍스트와 내용 요약을 장기 기억·대화 기억 요약으로 설명하지 않는다. Python API 호출과 공급자 웹검색 도구의 실제 호출 방식을 그대로 작성한다.

# True or Not Render 배포

기준일: 2026-10-12. 역할: 배포 설정·절차·완료 확인. 프론트는 Vercel Hobby, 백엔드·DB는 AIO 2기의 Render에 실제 배포했습니다. 백엔드 Live·DB Available·대화 테이블 생성·생존 응답·무키 차단과 Vercel Production 공유 값 연결·Ready를 확인했습니다. 공개 앱의 실제 검증 1건·저장 동의·HTTPS 익명 세션·실제 DB 조회가 통과했으며 대화 쓰기·복원 전체 시험과 부하 검증은 남아 있습니다. 현재 공백과 담당은 [작업현황](작업현황.md), 코드 동작은 [아키텍처](아키텍처.md)를 따릅니다.

## 구성과 환경 설정

[render.yaml](../render.yaml)은 사용자가 확인한 **AIO 2기** 워크스페이스에 FastAPI 백엔드와 PostgreSQL DB를 구성합니다. 강사 가이드 `2026_render_dev/STUDENT_GUIDE.md`의 내부 DB 연결·공유 키·디스크 1GB·분리된 프론트 원칙을 적용했습니다. 기존 강사 예제와 개인 워크스페이스의 DB는 변경하지 않습니다.

| 구성 | 플랫폼·플랜 | 위치·비용 |
|---|---|---|
| 프론트 `true-or-not` | Vercel Hobby, Production Ready | [배포 주소](https://true-or-not-ten.vercel.app), main `107a600`, Render 공유 키 연결 확인 |
| 백엔드 `true-or-not-backend` | Render `0.5c-512mb`, Live | [실제 백엔드](https://true-or-not-backend.onrender.com), Singapore, 월 $7 |
| DB `true-or-not-db` | Render `0.1c-256mb`, 디스크 1GB, Available | Singapore, 월 $6 + 디스크 $0.30 |

Render 예상 합계는 월 $13.30이며 사용 시간에 따라 청구됩니다. 실제 적용 화면의 요금을 다시 확인합니다.

| 서비스 | 설정 | 값·역할 |
|---|---|---|
| 백엔드 | Docker 컨텍스트 `backend`, [Dockerfile](../backend/Dockerfile) | `${PORT:-8010}`으로 바인딩, `/health` 생존 확인 |
| 백엔드 | `HIVE_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` | 사용할 공급자 키. 적어도 하나 필요, 없는 공급자는 건너뜀 |
| 백엔드 | `TAVILY_API_KEY`, `TYPESAFE_API_KEY`, `YOUTUBE_API_KEY`, `FINNHUB_API_KEY` | 선택 기능의 키. 실제 권한·지원 범위 별도 확인 |
| 백엔드 | `BACKEND_SHARED_SECRET` | Render 자동 생성, Vercel 공유 시크릿과 같은 값, `/health` 외 요청 헤더 보호 |
| 백엔드 | `DATABASE_URL` | Blueprint가 같은 리전 DB의 내부 연결 주소를 주입 |
| 백엔드 | `CONVERSATION_SESSION_SECRET` | Render 자동 생성, 익명 대화 소유권 토큰 서명 |
| 프론트 | Vercel Next.js 프로젝트 | Root Directory `./`, Next.js 프리셋, main Git 연동 |
| 프론트 | `FACTLENS_BACKEND_URL` | 실제 백엔드 HTTPS URL. Blueprint의 예시 주소와 대조 |
| 프론트 | `FACTLENS_ALLOW_REMOTE_BACKEND=1` | 원격 HTTPS 백엔드 허용 |
| 프론트 | `FACTLENS_PUBLIC_DEPLOY=1` | 기본 로컬 요청 정책을 공개 모드로 전환 |
| 프론트 | `FACTLENS_BACKEND_SECRET` | 백엔드와 동일, 서버 전용. `NEXT_PUBLIC_*`로 노출하지 않음 |
| 프론트 | `FACTLENS_ACCESS_PASSWORD` | 사용자가 정하는 공유 접속 비밀번호 12~256자, 서버 전용·Sensitive. 필요한 Production·Preview에 직접 등록 |

공급자 키는 Render의 `sync: false` 입력 칸 또는 Environment에서 직접 설정합니다. Vercel에는 백엔드 주소·공유 시크릿·접속 비밀번호를 설정하고 공급자 키·DB 접속 정보·대화 서명 키는 넣지 않습니다. [.dockerignore](../.dockerignore)와 [백엔드 제외 규칙](../backend/.dockerignore)은 `.env*`·가상환경·캐시를 제외합니다. 비밀값은 채팅·문서·로그·Git에 기록하지 않습니다.

## 공유 접속 비밀번호

2026-10-12 구현·로컬 검증을 완료했으며 운영 환경 변수 등록·PR 승인·공개 배포는 남아 있습니다. [실행 기록](qa/실행기록/2026-10-12-접속비밀번호.md)을 따릅니다.

1. 사용자가 Vercel Environment Variables에 `FACTLENS_ACCESS_PASSWORD`를 Sensitive 값으로 직접 등록합니다. 12자 이상 비밀번호를 선택하며 코드·채팅에 기록하지 않습니다. 기존 Render 연결 비밀키와 다른 값을 사용합니다.
2. 기존 `FACTLENS_BACKEND_SECRET`은 백엔드와 같은 32자 이상 비밀키를 유지합니다. 접속 쿠키의 서명에도 사용하며 브라우저에는 전달하지 않습니다. Preview는 별도 공유 키 연결 검증이 필요합니다.
3. 승인된 PR을 main에 반영하고 재배포합니다. 공개·프로덕션에서 필수 값이 없으면 비밀번호 화면에 관리자 문의 안내, API에 503을 반환합니다. 비밀번호·공개 플래그가 없는 로컬 개발은 기존처럼 동작합니다.
4. 로그인하면 24시간 `HttpOnly`·`SameSite=Lax`·HTTPS `Secure` 쿠키를 발급합니다. 홈과 모든 기존 API는 요청마다 서명을 검사하며, 미인증 API는 401로 차단합니다. 약관·개인정보 페이지는 공개합니다.
5. 로그아웃은 접속 쿠키만 삭제합니다. 비밀번호 변경·재배포는 이전 쿠키를 모두 무효화합니다. 기존 대화 소유권·저장 동의는 별도입니다. 공유 비밀번호 방식은 개인 계정·시도 속도 제한·사용량 제한을 추가하지 않습니다.

## 대화 저장 DB · Render PostgreSQL

2026-10-04 My Workspace에 `true-or-not-conversations` DB를 생성하고 두 테이블·저장소·익명 소유권 API·대화 UI를 로컬에서 검증했습니다. [당시 기록](qa/실행기록/2026-10-04-대화저장.md)을 보존합니다. 2026-10-12 사용자의 부트캠프 배포 요청에 따라 AIO 2기에 별도 `true-or-not-db`를 선언했으며 기존 개인 DB의 데이터 이동·삭제·유료 전환은 수행하지 않습니다.

아래는 완료된 DB 구성을 공개 웹서비스에 연결하거나 다른 개발 PC에서 재확인하는 절차다. DB 최초 생성과 T33 기능 구현을 미완료로 표시하지 않는다.

1. AIO 2기에 사용자가 지정한 유료 `0.1c-256mb`·디스크 1GB DB와 `0.5c-512mb` 백엔드를 생성합니다. 서비스 이름 충돌과 워크스페이스를 확인하며 강사 예제 리소스를 재사용하거나 변경하지 않습니다.
2. Render 백엔드는 내부 연결 주소를 서버 전용 `DATABASE_URL`로 사용한다. 로컬 개발은 외부 연결 주소와 TLS를 사용하고 외부 접근 허용 IP를 제한한다. 접속 URL의 비밀번호를 화면·로그·문서·Git에 기록하지 않는다.
3. `preDeployCommand: .venv/bin/python migrate_conversations.py`로 기존 반복 가능한 마이그레이션을 배포 전에 실행합니다. `conversations`·`messages` 테이블을 만들고 DB 작업 제한 3초·풀 최대 4개 및 저장 실패 시 LLM을 재호출하지 않는 동작을 유지합니다.
4. 실제 DB·로컬 브라우저 검증은 완료했다. T15·T34의 공개 환경에서는 새로고침·서버 재시작 후 복원, HTTPS 쿠키·타인 접근·무동의 차단, 삭제·중복 방지·DB 장애 및 저장 전후 지연을 다시 검증한다. [기획서의 대화 저장 수용 시험](기획서.md#대화-저장-수용-시험)을 따른다.

실제 생성한 DB는 무료 시연용이다. 공식 문서 확인일 2026-10-04 기준 무료 DB는 워크스페이스당 1개, 1GB, 생성 후 30일 만료이며 백업을 제공하지 않는다. 만료 뒤 14일 유예 기간이 지나면 데이터가 삭제되므로 지속 보관을 보장하지 않는다. 시연 종료 전 필요한 데이터를 안전하게 내보내거나 별도 승인 후 유료 전환을 결정한다. [무료 DB 제한](https://render.com/docs/free), [DB 생성·연결](https://render.com/docs/postgresql-creating-connecting).

## 배포 전 결정·보완

- D10~D13의 공개 대상·한도·동의·요금제·인스턴스를 확정하고 T10·T11을 반영한다. 공개 게이트와 서버 공유 시크릿만으로 사용자 제한이 생기지 않는다.
- 선택 기능·시연 입력을 정해 필요한 키와 권한만 확인한다. 미확인 기능은 공개·시연 범위에서 구분한다.
- 현재 `/health`의 리비전은 Git 조회에 의존한다. Docker에는 Git 저장소·커밋값 전달이 없어 T16의 배포 식별값 주입을 보완해야 한다.
- 무료 인스턴스 휴면·재시작과 장시간 스트림은 실제 선택한 요금제에서 확인한다. 현재 영속 작업 큐·재시작 후 복구는 없다.

## 적용 순서

1. 기존 작업 브랜치에서 공식 Blueprint 스키마·관련 회귀를 검증하고 PR로 main에 반영합니다. main 직접 push는 하지 않습니다.
2. AIO 2기의 Blueprint 생성 화면에서 저장소 `teach97/TRUE-OR-NOT`, main, 경로 `render.yaml`을 선택합니다. 백엔드·DB 두 리소스와 월 $13.30 예상 비용을 확인하고 필요한 공급자 키를 직접 입력합니다.
3. DB Available·백엔드 Live·마이그레이션 성공·`/health`를 확인합니다. Vercel의 `FACTLENS_BACKEND_URL`에 실제 HTTPS 주소, `FACTLENS_BACKEND_SECRET`에 백엔드 공유 값, 공개·원격 플래그에 `1`을 설정하고 재배포합니다. 생존 응답과 모델 연결 성공은 별도로 검사합니다.
4. 아래 원격 완료 기준을 실행하고 날짜·코드·환경·결과를 [QA 실행기록](qa/실행기록/)에 남긴다.

# True or Not 배포 구성 (Vercel + Render)

마지막 실환경 확인일: 2026-10-12. 문서 갱신일: 2026-10-13. 역할: 배포 설정·절차·완료 확인. 배포 구성은 브라우저 → Vercel Next.js 프런트·서버 프록시 → Render FastAPI 백엔드 → Render PostgreSQL입니다. 브라우저는 DB에 직접 접속하지 않으며, DB 연결 주소는 Render 백엔드에서만 사용합니다. 백엔드 Live·DB Available·대화 테이블 생성·생존 응답·무키 차단과 Vercel Production 공유 값 연결·Ready를 확인했습니다. 공개 앱의 실제 검증 1건·저장 동의·HTTPS 익명 세션·실제 DB 조회가 통과했으며 대화 쓰기·복원 전체 시험과 부하 검증은 남아 있습니다. 이번 문서 갱신에서는 외부 배포 상태를 다시 조회하지 않았습니다. 현재 공백과 담당은 [작업현황](작업현황.md), 코드 동작은 [아키텍처](아키텍처.md)를 따릅니다.

## 구성과 환경 설정

[render.yaml](../render.yaml)은 사용자가 확인한 **AIO 2기** 워크스페이스에 FastAPI 백엔드와 PostgreSQL DB를 구성합니다. 프런트엔드는 별도 Vercel 프로젝트에서 운영합니다. 강사 가이드 `2026_render_dev/STUDENT_GUIDE.md`의 내부 DB 연결·공유 키·디스크 1GB·분리된 프런트 원칙을 적용했습니다. 기존 강사 예제와 개인 워크스페이스의 DB는 변경하지 않습니다.

### 배포 구성

| 구성 | 플랫폼·플랜 | 위치·비고 |
|---|---|---|
| 프런트 `true-or-not` | Vercel Hobby, Production Ready (2026-10-12 확인) | [배포 주소](https://true-or-not-ten.vercel.app), main `107a600`, Render 공유 값 연결 확인 |
| 백엔드 `true-or-not-backend` | Render `0.5c-512mb`, Live (2026-10-12 확인) | [실제 백엔드](https://true-or-not-backend.onrender.com), Singapore |
| DB `true-or-not-db` | Render `0.1c-256mb`, 디스크 1GB, Available (2026-10-12 확인) | Singapore |

2026-10-12 당시 Render 예상 합계는 월 $13.30이었습니다. 현재 요금은 다시 확인하지 않았으므로 실제 적용 화면에서 확인해야 합니다.

| 서비스 | 설정 | 값·역할 |
|---|---|---|
| 백엔드 | Docker 컨텍스트 `backend`, [Dockerfile](../backend/Dockerfile) | `${PORT:-8010}`으로 바인딩, `/health` 생존 확인 |
| 백엔드 | `HIVE_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` | 사용할 공급자 키. 적어도 하나 필요, 없는 공급자는 건너뜀 |
| 백엔드 | `TAVILY_API_KEY`, `TYPESAFE_API_KEY`, `YOUTUBE_API_KEY`, `FINNHUB_API_KEY` | 선택 기능의 키. 실제 권한·지원 범위 별도 확인 |
| 백엔드 | `BACKEND_SHARED_SECRET` | Render 자동 생성, Vercel 공유 시크릿과 같은 값, `/health` 외 요청 헤더 보호 |
| 백엔드 | `DATABASE_URL` | Blueprint가 같은 리전 DB의 내부 연결 주소를 주입 |
| 백엔드 | `CONVERSATION_SESSION_SECRET` | Render 자동 생성, 익명 대화 소유권 토큰 서명 |
| 프론트 | Vercel Next.js 프로젝트 | Root Directory `./`, Next.js 프리셋, main Git 연동 |
| 프론트 | `FACTLENS_BACKEND_URL` | 실제 백엔드 HTTPS URL. Blueprint의 예시 주소와 대조 |
| 프론트 | `FACTLENS_ALLOW_REMOTE_BACKEND=1` | 원격 HTTPS 백엔드 허용 |
| 프론트 | `FACTLENS_PUBLIC_DEPLOY=1` | 기본 로컬 요청 정책을 공개 모드로 전환 |
| 프론트 | `FACTLENS_BACKEND_SECRET` | 백엔드와 동일, 서버 전용. `NEXT_PUBLIC_*`로 노출하지 않음 |
| 프론트 | `FACTLENS_ACCESS_PASSWORD` | 사용자가 정하는 공유 접속 비밀번호 4~256자, 서버 전용·Sensitive. 필요한 Production·Preview에 직접 등록 |

공급자 키는 Render의 `sync: false` 입력 칸 또는 Environment에서 직접 설정합니다. Vercel에는 백엔드 주소·공유 시크릿·접속 비밀번호를 설정하고 공급자 키·DB 접속 정보·대화 서명 키는 넣지 않습니다. [.dockerignore](../.dockerignore)와 [백엔드 제외 규칙](../backend/.dockerignore)은 `.env*`·가상환경·캐시를 제외합니다. 비밀값은 채팅·문서·로그·Git에 기록하지 않습니다.

## 공유 접속 비밀번호

2026-10-12 구현·로컬 검증을 완료했습니다. [작업현황](작업현황.md)의 2026-10-13 기록 기준으로 Production Secret 등록과 PR #7 병합·배포 승인이 확인되었으며, 공개 환경의 전체 수용 시험은 남아 있습니다. 이번 문서 갱신에서는 현재 프로덕션 동작을 다시 확인하지 않았습니다. [실행 기록](qa/실행기록/2026-10-12-접속비밀번호.md)을 따릅니다.

1. 각 Vercel 환경에 `FACTLENS_ACCESS_PASSWORD`를 Sensitive 값으로 등록합니다. Production 등록은 작업현황의 2026-10-13 기록에서 확인했으며 Preview 등 다른 환경은 별도로 설정해야 합니다. 4자 이상 비밀번호를 선택하고 코드·채팅에 기록하지 않습니다. 기존 Render 연결 비밀키와 다른 값을 사용합니다.
2. 기존 `FACTLENS_BACKEND_SECRET`은 백엔드와 같은 32자 이상 비밀키를 유지합니다. 접속 쿠키의 서명에도 사용하며 브라우저에는 전달하지 않습니다. Preview는 별도 공유 키 연결 검증이 필요합니다.
3. 변경 코드가 프로덕션에 반영되지 않은 환경이라면 승인된 PR을 main에 반영하고 재배포한 뒤 Ready를 확인합니다. 공개·프로덕션에서 필수 값이 없으면 비밀번호 화면에 관리자 문의 안내, API에 503을 반환합니다. 비밀번호·공개 플래그가 없는 로컬 개발은 기존처럼 동작합니다.
4. 로그인하면 24시간 `HttpOnly`·`SameSite=Lax`·HTTPS `Secure` 쿠키를 발급합니다. 홈과 모든 기존 API는 요청마다 서명을 검사하며, 미인증 API는 401로 차단합니다. 약관·개인정보 페이지는 공개합니다.
5. 로그아웃은 접속 쿠키만 삭제합니다. 비밀번호 변경·재배포는 이전 쿠키를 모두 무효화합니다. 기존 대화 소유권·저장 동의는 별도입니다. 공유 비밀번호 방식은 개인 계정·시도 속도 제한·사용량 제한을 추가하지 않습니다.

## 대화 저장 DB · Render PostgreSQL

2026-10-04 My Workspace에 `true-or-not-conversations` DB를 생성하고 두 테이블·저장소·익명 소유권 API·대화 UI를 로컬에서 검증했습니다. [당시 기록](qa/실행기록/2026-10-04-대화저장.md)을 보존합니다. 2026-10-12 사용자의 부트캠프 배포 요청에 따라 AIO 2기에 별도 `true-or-not-db`를 선언했으며 기존 개인 DB의 데이터 이동·삭제·유료 전환은 수행하지 않습니다.

2026-10-12 AIO 2기에 Render 백엔드와 PostgreSQL을 배포하고 Vercel Production에 연결했습니다. 아래 초기 생성 절차는 당시 적용 이력이며 현재 리소스를 다시 만들라는 지시가 아닙니다.

1. 초기 배포에서 AIO 2기에 사용자가 지정한 `0.1c-256mb`·디스크 1GB DB와 `0.5c-512mb` 백엔드를 생성했습니다. 서비스 이름 충돌과 워크스페이스를 확인했으며 강사 예제 리소스는 재사용하거나 변경하지 않았습니다.
2. Render 백엔드는 내부 연결 주소를 서버 전용 `DATABASE_URL`로 사용한다. 로컬 개발은 외부 연결 주소와 TLS를 사용하고 외부 접근 허용 IP를 제한한다. 접속 URL의 비밀번호를 화면·로그·문서·Git에 기록하지 않는다.
3. `preDeployCommand: .venv/bin/python migrate_conversations.py`로 `migrations/*.sql`을 이름순으로 배포 전에 실행합니다. `001_conversations.sql`이 테이블을 만들고 `002_conversation_expiry.sql`이 `expires_at`과 인덱스를 추가·이관합니다. 두 파일은 반복 실행 가능하며 DB 작업 제한 3초·풀 최대 4개를 유지합니다. 로컬 백엔드를 갱신할 때도 서버 시작 전에 같은 마이그레이션을 실행합니다.
4. 실제 DB·로컬 브라우저 검증과 공개 앱의 저장 동의·HTTPS 익명 세션·DB 조회는 확인했습니다. 새로고침·서버 재시작 후 복원, 타인 접근·무동의 차단, 삭제·중복 방지·DB 장애 및 저장 전후 지연의 전체 공개 환경 시험은 남아 있습니다. [기획서의 대화 저장 수용 시험](기획서.md#대화-저장-수용-시험)을 따릅니다.

대화 만료 정리는 별도 서버·유료 Cron 없이 FastAPI 수명 주기에서 실행합니다. 시작 시와 이후 매시간 `expires_at`이 지난 대화 행을 삭제하고 연결 메시지는 외래 키로 함께 삭제합니다. 서버·DB 중단 시 정리는 지연되며 재시작·다음 주기에 재시도합니다. 기존 기록은 소유자별 첫 대화 생성일 + 30일로 이관하고, 신규 기록은 검증된 세션의 원래 만료 시각을 저장합니다. 앱의 보관 정책과 아래 과거 무료 DB 인스턴스의 서비스 만료는 별개입니다.

2026-10-04 My Workspace에 생성한 DB는 무료 시연용입니다. 아래 무료 제한은 그 DB에만 해당하며, 공개 서비스에는 AIO 2기에 별도로 만든 Render DB를 연결했습니다. 공식 문서 확인일 2026-10-04 기준 무료 DB는 워크스페이스당 1개, 1GB, 생성 후 30일 만료이며 백업을 제공하지 않습니다. 만료 뒤 14일 유예 기간이 지나면 데이터가 삭제되므로 지속 보관을 보장하지 않습니다. 해당 My Workspace DB의 보관이 필요하면 시연 종료 전 내보내거나 별도 승인 후 유료 전환을 결정합니다. [무료 DB 제한](https://render.com/docs/free), [DB 생성·연결](https://render.com/docs/postgresql-creating-connecting).

## 추가 공개·운영 전 결정·보완

- 공개 범위·공통 호출 한도·운영 및 DB 지속 비용을 확정하고 T10·T11·T26을 점검한다. 배포되어 있다는 사실이나 서버 공유 시크릿만으로 이용자별 호출 제한이 생기지는 않는다.
- 선택 기능·시연 입력을 정해 필요한 키와 권한만 확인한다. 미확인 기능은 공개·시연 범위에서 구분한다.
- 현재 `/health`의 리비전은 Git 조회에 의존한다. Docker에는 Git 저장소·커밋값 전달이 없어 T16의 배포 식별값 주입을 보완해야 한다.
- 무료 인스턴스 휴면·재시작과 장시간 스트림은 실제 선택한 요금제에서 확인한다. 현재 영속 작업 큐·재시작 후 복구는 없다.

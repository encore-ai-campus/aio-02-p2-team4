# True or Not PRD (현행 코드 기준)

기준일: 2026-10-08. 이 문서는 현재 코드와 실측을 기준으로 제품 요구사항을 정리한 것이다. 정책·배경은 [기획서](기획서.md), 구현 구조는 [아키텍처](아키텍처.md), 완료·잔여·미결정은 [작업현황](작업현황.md), 배포 절차는 [배포](배포.md)를 따른다.

## 1. 제품 개요

True or Not은 기사·댓글·온라인 주장에 의문을 가진 사용자가 개별 주장과 근거를 추적·비교하는 생활형 검증 도구다. 정답을 선언하지 않고, 확인된 내용과 불확실한 내용을 원문 인용과 함께 보여준다.

- 입력: 텍스트·링크·이미지 + 확인 요청 + 외부 전송 동의
- 처리: LangGraph 5단계(추출→검색→읽기→판정→합성) + 최대 1회 재탐색
- 출력: 주장별 판정 카드, AI 개요, 출처·인용, 경고, JSON 내보내기

## 2. 기능 요구사항

| ID | 기능 | 현재 동작 |
|---|---|---|
| FR-01 | 주장 추출 | 최대 3개, 원문 위치(UTF-16) 검증. 후보 선택 없이 자동 실행 |
| FR-02 | 확인 요청·동의 | 본문 12,000자·확인 요청 500자, `consent=true` 필수. 첫 외부 호출 전 최초 동의 1회 |
| FR-03 | 검색 | Tavily 우선, 없거나 실패 시 LLM 웹검색 대체. 출처 최대 6개·동일 사이트 2개 |
| FR-04 | 원문 읽기 | 출처 최대 4건 병렬 수집. 접근 실패는 `unavailable`로 표시하고 근거로 쓰지 않음 |
| FR-05 | 주장별 판정 | 7종 판정 코드. LLM 제안 → 인용·참조 무결성 코드 검증, 규칙 우선 |
| FR-06 | AI 개요 | 검증된 원문 인용으로 합성. 상태 3종(`grounded`·`insufficient_evidence`·`synthesis_failed`) |
| FR-07 | JEV 빠른 경로 | 검색→읽기→TypeSafe 판정, 점수만 반환. 이미지 거부 |
| FR-08 | 내용 요약 | 텍스트·링크·30분 미만 자막 요약. 판정 없음 |
| FR-09 | 시장 맥락 | 종목 탐지 시 Finnhub 시세·60일봉. 실패해도 검증 계속, 매매 권고 아님 |
| FR-10 | 유튜브 맥락 | 자막은 판정 근거 가능, 제목·댓글(최대 10개)은 참고용. API 메타데이터는 내보내기 제외 |
| FR-11 | 진행·취소·재시도 | NDJSON 스트림, 브라우저 취소 전파, 늦은 응답 무시, 메인 프록시 동시 10건(초과 429) |
| FR-12 | 대화 저장 | PostgreSQL 저장·목록·복원·이어쓰기·삭제. 기본 꺼짐·HttpOnly 서명 쿠키 익명 소유권 |
| FR-13 | 데모·내보내기 | 합성 예시 구분 표시, 결과 JSON 다운로드 |

## 3. 비기능 요구사항

| ID | 항목 | 기준 |
|---|---|---|
| NFR-01 | 응답 시간 | 실측 40~207초/건. 판정·합성이 전체의 90%. 재탐색 발동 시 +24~110초 |
| NFR-02 | 동시성 | 메인 검증 10건, 원문 수집 4건 병렬, DB 풀 4개·작업 3초 |
| NFR-03 | 비용 | 유료 호출은 사전 승인 후 실행. 동일 질문 재검증 캐시 없음 |
| NFR-04 | 보안·개인정보 | 키는 서버 환경에만. 얼굴·개인정보 분석·로그인 범위 밖 |
| NFR-05 | 품질 게이트 | 머지 전 BE·FE 테스트·타입 통과. 현재 BE 508개·FE 113개 통과 |

## 4. API 계약

| 메서드·경로 | 용도 |
|---|---|
| `GET /health` | 생존 확인 (인증 예외) |
| `GET /api/fact-check` | 모델·설정·워크플로 상태 |
| `POST /api/fact-check` | 단일 JSON 검증 |
| `POST /api/fact-check/stream` | NDJSON 스트림 (프론트 주 경로) |
| `POST /api/fact-check/jev` | JEV 빠른 판정 |
| `POST /api/intent` | 의도 분류·일반 답변 |
| `POST /api/summarize` | 내용 요약 |
| `/api/conversations/*` | 대화 저장 API (상태·세션·목록·생성·복원·추가·삭제) |

## 5. 수용 기준 (발췌)

- 공백·상한 초과 입력은 전송 차단하고 이유를 안내한다.
- 의견·예측은 `검증 대상 아님`으로, 근거 없으면 `근거 부족`으로, 기술 실패는 `synthesis_failed`로 구분한다.
- 원문에 없는 인용은 제외하고 판정을 재평가한다. 인용 삐끗(공백·따옴표)은 원문 구간으로 교정한다.
- 재탐색은 인용 탈락 또는 접근 불가 엄격 과반일 때만 최대 1회 수행한다.
- "정확도 ○%" 같은 미측정 수치는 홍보하지 않는다.

## 6. 범위 밖

전체 크롤링·SNS 감시, 작성자 평가, 개인정보·얼굴 분석, 자동 신고·차단, 의학·법률·투자 판단, 영상·음성 자체 분석, 로그인·기기 간 동기화·공유, 다중 에이전트·장기 기억 요약·벡터 검색.

## 7. 잔여 작업

공개 배포 실실행, 배포 식별값 주입, 공개 환경 검증, 합성 데드라인, 검색 캐시, JEV 세부·점수 정책·호출 한도 수치 등 미결정 확정. 상세는 작업현황의 T15·T16·T34·D1·D11·D13·D15를 따른다.

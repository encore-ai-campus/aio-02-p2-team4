## 의도 분류 인증 오류 디버그 (2026-10-12)

- 401·403을 `PROVIDER_AUTH_FAILED`로 전달하고 화면에 인증·접근 권한 문제로 표시합니다. 일반 기술 오류도 확인 질문과 구분합니다. 공급자 원문·키는 전달하지 않고 기존 HTTP 상태 진단을 보존합니다.
- 수정 전 BE 인증 회귀 4개·FE 프록시 회귀 1개·HTTP 상태 보존 회귀 2개가 실패했고, 수정 후 전체 FE 129개·BE 449개·타입·webpack 빌드·Chrome 회귀를 통과했습니다. 명시적 모델 단독 호출·Auto 폴백·취소·동의 정책을 유지합니다.
- 원격의 명시적 검증 요청 폴백을 보존합니다. 인증 거절이 확인된 경우에만 폴백을 차단하여 같은 모델의 추가 검증 요청을 방지합니다. 해당 회귀는 수정 전 실패·수정 후 통과했습니다.
- 사용자가 키 갱신을 완료했습니다. 이전 환경변수 상속을 제외한 진단에서 실제 분류 200·`verify/current`(1.16초)를 확인하고 사용자 백엔드에 적용했습니다. 사용자 3000 프록시의 원래 입력도 200·`verify/current`(1.09초)로 통과했습니다. 환경 파일·시스템 환경변수는 직접 열거나 수정하지 않았습니다.
- 사용자 3000 개발 프론트·8010 백엔드는 유지하고 시험 3017·8017 포트·탭은 종료했습니다. 전체 검증 정확도·전체 응답 지연은 별도입니다. 향후 실행에서도 파일의 새 키를 이전 프로세스 환경변수가 덮지 않도록 관리해야 합니다.
- [실행 기록](../qa/실행기록/2026-10-12-의도분류인증.md)을 참조합니다. 기존 `feat/agent`에 반영합니다.
